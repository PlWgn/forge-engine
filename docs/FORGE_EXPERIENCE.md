# Опыт создания «Последней смены» на Forge 1.2.1

Игра создана 3–4 октября 2026 года на macOS arm64. Это отчёт о работе с данной копией. C++-ядро осталось неизменным: игровой код использует публичный Python API.

## Что помогло

- Сцена с `on_start`, `forge.spawn`, Entity, текст, ввод и звук позволили собрать игровой цикл без нативного расширения.
- `screen=True`, порядок по Z и clipping достаточны для офиса, монитора, карты, меню и эффектов. Кириллица работает сразу.
- SaveManager предоставил atomic replace, checksum, backup и версию. Формат сохранений не пришлось создавать с нуля.
- Аудиоканалы и fade отделили атмосферу, эффекты и голос. `on_frame` позволил сохранить интерфейс при остановленной физике.
- Headless позволяет проверять логику внутри настоящего runtime. Упаковщик успешно перенёс CPython и нативные библиотеки в самостоятельную сборку.

## Чего не хватило под капотом

### Рендеринг

Нет публичного viewport/render target для камер. Здесь камеры — подготовленные 2D-позиции, а не девять параллельно рендерящихся 3D-камер. Это подходит форме игры, но живое видеонаблюдение за 3D-миром потребовало бы расширения renderer.

Нет texture-region/UV-rectangle API, атласов и эффективной пакетной отрисовки. Персонажи — отдельные прозрачные PNG; скриммеры анимированы перемещением, масштабом и вращением. Для покадровой анимации нужны sprite-sheet API и batching.

Нет готовой постобработки и управления shader uniforms из Python. Помехи и CRT-линии пришлось рисовать экранными объектами. Grain, bloom, aberration и переход монитора логичнее выполнять полноэкранным проходом.

Штатный шрифт не содержит часть декоративных символов. Заменил стрелки и отметки на поддерживаемые символы. Нужны fallback-fonts и диагностика missing glyphs.

Ресурсы загружаются и проверяются синхронно. Для большого контента нужны asset handles, preload по сценам, фоновая загрузка и бюджеты памяти.

### Интерфейс и ввод

Для авторского интерфейса написан собственный слой View: сохранение Entity между кадрами, масштабирование 16:9, панели, порядок кликабельных элементов и блокировка ввода под паузой. Встроенные компоненты полезны, но для полностью оформленного продукта нужны стили, переходы, навигация и управление состояниями.

Не хватает input action map, переназначения клавиш, controller support и событий ввода. Сейчас игра напрямую опрашивает клавиши.

Текст выводится отдельными draw calls для глифов. Много текста означает много обращений OpenGL. Нужны atlas/batching и профайлер затрат по подсистемам.

### Звук

Каналы и fade работают, но нет публичного stereo pan, spatial audio и DSP-фильтров. Шаги заранее синтезированы в стерео: через API нельзя просто расположить источник у левой двери.

Нет встроенного механизма синхронизированных субтитров. Полный текст инструктажа доступен перед ночью; голосовой WAV запускается отдельно и пропускается M.

Для больших игр нужны ducking, ограничения voice count, streaming policy и диагностика аудио. Здесь микширование контролируется игровым кодом.

### Цикл, физика и состояние

Простая физика перебирает пары всех Entity, включая экранные объекты без коллайдера. Эта игра не использует физические тела: оставил физику на паузе, а модель выполняю через on_frame. Лучше иметь отдельный переключатель физики и отдельные списки активных colliders.

Нет AI scheduler, state machine, таймлайнов и последовательностей. Четыре поведения врагов и переходы между состояниями реализованы в Python. Модель отделена от Forge, что позволило проверить все ночи на 180 начальных seeds.

Откат reload не делает транзакционными записи Python в файлы. Запись прогресса и настроек вынесена в конкретные действия. Для большой игры нужен явный контракт между reload и persistence.

Нет записи и воспроизведения реального ввода. Для регрессий пришлось имитировать физический ввод на публичном API и сделать автоматический обход экранов.

### Поставка

Упаковщик создаёт каталог, но не готовое `.app`. LaunchServices-обёртка, Info.plist и launcher добавлены отдельно. Эта сборка рассчитана на локальный запуск; Developer ID signing/notarization для публикации не выполнены.

Лог и сохранения находятся возле исполняемого файла. Не хватает API пользовательских каталогов Application Support/AppData, отделённых от папки игры. Текущее место хранения описано в README.

Не хватает end-user настроек окна/полноэкранного режима и crash reporter. JSON-конфигурация и журнал помогают разработчику, но не заменяют инструменты поставки продукта.

## Приоритеты развития

Для небольших хорроров прежде всего полезны texture regions/batching, постобработка, pan/DSP, action map, пользовательские каталоги и упаковка в приложения. Для свободно исследуемого 3D-хоррора дополнительно нужны character controller, освещение и тени, skeletal animation, современные форматы моделей и редактор сцен.
