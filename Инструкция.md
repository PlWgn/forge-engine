# Forge — инструкция по разработке игр

Forge — C++17-движок с пользовательскими сценами и поведением на Python. Ядро создаёт окно, выполняет игровой цикл, предоставляет модули, проверяет ресурсы и собирает переносимую папку игры. Разработчик игры редактирует конфигурацию и контент; изменения C++-ядра для этого не нужны.

Доступны 2D-спрайты, текст с кириллицей, перспективная 3D-камера, кубы, OBJ-модели, материалы и GLSL-шейдеры, клавиатура и мышь, звук WAV/MP3/FLAC, простая физика AABB, триггеры, raycast, сохранения и автоматическое обновление контента. Forge 2.0 предоставляет встроенную локализацию (раздел 10.5), готовый UI, раскладку и перенос текста, меню, надёжные слоты, каналы звука и затухание. Сцены для платформера, новеллы и 3D-проекта используют один и тот же API.

## 1. Установка

### macOS

Нужны Command Line Tools (`xcode-select --install`), Python 3.10+ с development headers и CMake 3.24+. Для переносимых сборок рекомендуется Python с python.org; движок собирается под архитектуру используемого Python. Системный Python от Apple для этой цели не рекомендуется.

```sh
python3 -m venv .tools
source .tools/bin/activate
python -m pip install cmake==3.31.6
python tools/dependencies.py
python tools/forge.py compile
```

`dependencies.py` скачивает фиксированные версии библиотек и свободный шрифт. Интернет нужен только для установки зависимостей; компиляция после этого работает без сети. Скрипт использует проверку TLS; при ошибке сертификатов исправьте сертификаты установленного Python, не отключайте проверку.

В чистой копии репозитория нет `.tools`, `build`, `dist` и скачанных библиотек: они исключены из Git. В `vendor` находятся только описание и lock-файл. Приведённые команды создают локальное окружение, загружают зависимости и компилируют движок. Сведения о прошлых локальных проверках в Проверка.md не означают наличия готовых бинарных файлов в вашей копии.

### Windows

Установите Visual Studio 2022 Build Tools с Desktop development with C++, Windows SDK, CPython x64 с python.org и CMake. Выполняйте команды в Developer PowerShell/Native Tools Command Prompt:

```powershell
python -m venv .tools
.tools\Scripts\Activate.ps1
python -m pip install cmake==3.31.6
python tools/dependencies.py
python tools/forge.py compile
python tools/forge.py dev
```

Все компоненты должны иметь одну архитектуру: например x64. При запрете активации venv запускайте `.tools\Scripts\python.exe` напрямую. MSVC получает `/utf-8` для русских строк в исходниках.

CMake собирает `build/bin/forge` на macOS и обычно `build/bin/Release/forge.exe` на Windows. Python launcher автоматически находит соответствующий файл. OpenGL 3.3 Core должен поддерживаться драйвером видеокарты; macOS использует forward-compatible Core context.

## 2. Быстрый старт

После установки зависимостей и компиляции из раздела 1, из корня движка:

```sh
python tools/forge.py validate
python tools/forge.py dev
python tools/forge.py run
python tools/forge.py build --output dist/MyGame
python tools/forge.py test
```

Если оболочка на macOS не активировала `.tools`, используйте `python3` или `.tools/bin/python`.

- `compile` — конфигурация CMake и компиляция самого C++-движка. Нужна один раз и при изменениях C++-модулей.
- `configure` — только генерация файлов CMake.
- `validate` — проверка конфигурации, ресурсов, декодирования текстур/OBJ, JSON-объектов и синтаксиса всех Python-файлов.
- `dev` — немедленный запуск проекта с обновлением сцен и ресурсов без build игры.
- `run` — запуск текущего контента без наблюдения за файлами.
- `build` — проверка и создание самостоятельной папки игры с ресурсами, исполняемым файлом и Python.
- `test` — интеграционные проверки настоящего C++-runtime.
- `init --output путь` — создание нового проекта из стартового набора. Папка должна быть пустой.

C++ является компилируемым языком: первый запуск ядра требует его компиляции. Повторные запуски и редактирование Python/JSON/ресурсов не требуют пересборки C++. `build` игры упаковывает уже собранный runtime; Python-код интерпретируется и в dev, и в готовой игре.

Прямой запуск ядра:

```sh
./build/bin/forge dev --project engine.json
./build/bin/forge validate --project engine.json
./build/bin/forge run --headless --frames 120 --no-open-log
./build/bin/forge build --output dist/MyGame
```

`--headless` выполняет логику и физику без окна и звукового устройства. Шаг времени в этом режиме — 1/60 секунды. `--frames N` ограничивает число кадров, `--no-open-log` отключает только автоматическое открытие журнала. Журналирование остаётся включённым. Процесс возвращает 0 при успехе, 1 при ошибке. В dev ошибка при обновлении приостанавливает сценарий; исправление файла позволяет продолжить после reload.

Стартовая сцена: A/D — движение, Space — прыжок, Enter — следующая реплика, F5 — сохранение со звуком, 2 — 3D, 3 — готовый интерфейс. В 3D: WASD — свободная камера, стрелки — обзор, удержание M — обзор мышью, 1 — 2D. Escape завершает игру.

## 3. Структура и независимость ядра

```text
engine.json          — общие настройки и первая сцена
engine/              — исходники защищённого архитектурой C++-ядра
  include/forge/     — публичные заголовки для C++-модулей
  src/               — запуск, конфигурация, мир, графика, Python, звук, логирование
graphics/            — шейдеры и шрифт
modules/             — общие Python-модули и дополнительные C++-модули
scenes/              — JSON- и Python-сцены
scripts/             — поведение объектов и startup-скрипты
textures/            — PNG/JPEG и другие форматы stb_image
materials/           — JSON-материалы
models/              — OBJ
objects/             — JSON-шаблоны объектов
audio/               — аудиофайлы
locales/             — JSON-словари переводов
saves/               — создаётся при первом сохранении
forge.log            — журнал в корне текущего проекта
build/               — результат компиляции ядра
dist/                — собранные игры
```

Названия всех папок контента можно менять в `paths`. Вложенные папки поддерживаются. Файлы тоже можно переименовывать, обновив ссылки на них. Никаких жёстко заданных путей `scenes/` или `textures/` в пользовательском API нет. Имя самого settings-файла свободное: передайте его через `--project`.

Пути — относительно папки settings-файла. Ссылки на texture/model/script/prefab — относительно своей группы в `paths`. Абсолютные пути и выход через `..` за корень запрещены, включая символические ссылки наружу. Новые группы можно добавлять в `paths` и получать через `forge.asset_path(group, file)`. Не используйте корень проекта как папку ассетов: для сборки требуются отдельные папки ресурсов.

Создать отдельную игру, сохранив общее ядро:

```sh
python /path/to/engine/tools/forge.py init --output /path/to/MyGame
python /path/to/engine/tools/forge.py dev --project /path/to/MyGame/engine.json
python /path/to/engine/tools/forge.py build --project /path/to/MyGame/engine.json --output /path/to/releases/MyGame
```

C++-ядро здесь одно, игровой контент находится в отдельной папке. При подключении C++-модулей конкретной игры выполните `compile --project /path/to/MyGame/engine.json`, чтобы включить их в runtime.

## 4. engine.json

```json
{
  "schema_version": 1,
  "project": {"name": "My Game", "version": "1.0.0", "icon": "textures/icon.png"},
  "entry_scene": "main.json",
  "paths": {
    "graphics": "graphics", "modules": "modules", "scenes": "scenes",
    "scripts": "scripts", "textures": "textures", "materials": "materials",
    "models": "models", "objects": "objects", "audio": "audio", "locales": "locales"
  },
  "window": {"width": 1280, "height": 720, "vsync": true, "resizable": true, "fullscreen": false},
  "renderer": {"vertex_shader": "default.vert", "fragment_shader": "default.frag", "font": "font.ttf"},
  "logging": {"open_on_error": true},
  "startup_scripts": ["startup.py"],
  "python_paths": [],
  "native_modules": [],
  "save_directory": "saves"
}
```

`schema_version`, `project.name`, `entry_scene` и базовые группы `paths` обязательны. Пустые папки ресурсов допустимы, отсутствующие — ошибка. Иконка — путь относительно корня; в Windows используется для окна. macOS игнорирует оконную иконку GLFW: пакет в текущей версии представляет собой каталог с бинарным файлом, а не `.app`.

`startup_scripts` запускаются один раз при запуске приложения и остаются между сменами сцен. Можно определить `on_start()`, `on_update(dt)`, `on_destroy()`. `python_paths` — дополнительные папки Python-пакетов внутри проекта; они включаются в сборку. `native_modules` — пути к дополнительным `.cpp`; они компилируются в ядро.

Пользовательские поля JSON разрешены; получить их можно через `forge.settings()`. Неизвестные поля не становятся автоматически новыми функциями ядра: это метаданные для ваших модулей.

## 5. JSON-сцена

```json
{
  "mode": "3d",
  "background": [0.03, 0.04, 0.07, 1],
  "gravity": [0, -9.81, 0],
  "camera": {"position": [0, 2, 7], "target": [0, 1, 0], "fov": 60},
  "script": "main.py",
  "entities": [
    {
      "id": "player", "prefab": "player.json", "position": [0, 2, 0],
      "scripts": [{"file": "player.py", "properties": {"speed": 5}}]
    }
  ]
}
```

`script` — необязательный Python-файл относительно `paths.scenes`, с событиями сцены `on_start()`, `on_update(dt)`, `on_destroy()`. `entities` — список объектов. `id` уникален в сцене; по нему работает `forge.find()`. Без `id` движок генерирует имя, но для стабильных ссылок задавайте его явно.

2D: координаты в логических пикселях окна, X вправо, Y вниз. Камера сдвигает мир по X/Y. Спрайт центрирован в `position`, `scale` задаёт размеры. `position.z` определяет порядок 2D-слоёв: больше рисуется позже. UI с `screen: true` рисуется после мира и не зависит от камеры.

3D: X вправо, Y вверх, единицы произвольные. Камера перспективная; `target` — точка взгляда, `fov` в градусах. Не ставьте target в position и не направляйте камеру строго параллельно её вертикали. Встроенный куб имеет размер 1×1×1. `rotation` — градусы вокруг X/Y/Z. OBJ использует координаты из модели. Базовое освещение направленное, без теней.

## 6. Python-сцена

`entry_scene` может указывать на `.py`:

```python
import forge

def build():
    return {
        'mode': '2d',
        'gravity': [0, 980, 0],
        'entities': [
            {'id': 'title', 'kind': 'text', 'text': 'Привет!',
             'position': [40, 40, 0], 'font_size': 30, 'screen': True}
        ]
    }

def on_start():
    forge.log('Сцена готова')

def on_update(dt):
    if forge.key_pressed('ENTER'):
        forge.change_scene('level2.json')

def on_destroy():
    forge.log('Сцена выгружена')
```

`build()` необязателен. Он может вернуть словарь с описанием сцены, вернуть None или создавать объекты через `forge.spawn()`. При возврате None можно вызвать `set_mode`, `set_background`, `set_gravity`, `set_camera` напрямую. Возвращённое описание читается после выполнения build; не дублируйте создание одних и тех же объектов в обоих подходах.

Переход сцены откладывается до начала следующего кадра; последние запросы в кадре имеют приоритет. Старая сцена сохраняется до успешной инициализации новой. После перехода старые ссылки на Entity имеют `alive == False`. Объекты сцен не сохраняются автоматически между сценами: используйте startup-модуль или файлы сохранений для общего состояния.

## 7. Объекты, шаблоны и материалы

Поддерживаемые `kind`: `sprite`, `cube`, `mesh`, `text`, `empty`. `empty` удобен для триггеров и логических объектов.

| Поле | Значение |
| --- | --- |
| id, name | Идентификатор и отображаемое имя |
| prefab | JSON-шаблон из paths.objects |
| position, rotation, scale | Векторы из трёх чисел |
| color | RGBA, четыре числа, обычно 0..1 |
| texture | Файл из paths.textures |
| model | OBJ из paths.models, нужен для mesh |
| material | JSON из paths.materials |
| text, font_size | UTF-8-текст и высота шрифта в пикселях |
| text_key, text_params | Ключ локализации и JSON-параметры перевода, см. 10.5 |
| visible | Отрисовка; false не отключает скрипты или физику |
| screen | UI поверх мира без камеры и depth test |
| collider | Полные размеры AABB, независимо от scale |
| dynamic, mass, velocity | Участие в интеграции физики, масса > 0 и скорость |
| trigger | События пересечения без физического разрешения |
| scripts | Список файлов или объектов file/properties |
| data | Пользовательские JSON-данные |

JSON-объекты, результаты Python build() и forge.spawn проходят один валидатор после объединения с prefab. Координаты, rotation/scale/velocity/collider, RGBA и clip должны содержать числовые компоненты, конечные и представимые в C++ float; bool, null-компоненты, NaN/Infinity и значения вроде 1e100 не допускаются. Масса и размер шрифта должны быть положительными после преобразования в float. Кроме того, обратная масса должна помещаться в float: например, mass=1e-40 отклоняется и в JSON, и в forge.spawn, и при присваивании Entity.mass. clip=null отключает ограничение. Присваивание числовых свойств Entity, move и impulse также проверяется до изменения объекта; при ошибке прежнее значение сохраняется.

Шаблон `objects/crate.json`:

```json
{"kind": "cube", "model": "", "scale": [1, 1, 1], "material": "wood.json", "collider": [1, 1, 1]}
```

Материал `materials/wood.json`:

```json
{"color": [1, 1, 1, 1], "texture": "wood.png"}
```

Материал устанавливает цвет и текстуру; явные поля объекта имеют приоритет. Шаблон и локальные поля объединяются JSON Merge Patch: локальные значения заменяют базовые, массивы заменяются целиком, null удаляет поле. Вложенное наследование prefab не поддерживается.

Текстуры: PNG/JPEG/BMP/TGA и другие форматы stb_image. Координата V направлена сверху вниз. OBJ: позиции, UV, нормали, отрицательные индексы, триангуляция граней. Отсутствующие нормали вычисляются по грани. MTL не загружается: материалы задаются отдельным JSON. Для сложных вогнутых многоугольников триангулируйте модель при экспорте.

Материал считывается при создании объекта. Изменить цвет или текстуру в игре можно свойствами Entity. Изменение JSON-материала в dev пересоздаёт сцену.

## 8. Поведение объекта

`scripts/player.py`:

```python
import forge

class Behavior:
    def __init__(self, entity, properties):
        self.entity = entity
        self.speed = properties.get('speed', 240)

    def on_start(self):
        forge.log(f'Создан {self.entity.name}')

    def on_update(self, dt):
        direction = forge.key_down('D') - forge.key_down('A')
        self.entity.move(direction * self.speed * dt, 0)

    def on_collision(self, other):
        if other: forge.log(f'Контакт: {other.id}')

    def on_collision_exit(self, other):
        # other может быть None, если второй объект уже удалён.
        if other: forge.log(f'Контакт завершён: {other.id}')

    def on_destroy(self):
        forge.log('Объект удалён')
```

Объекты можно создавать в `Behavior.on_start()`, `on_update()` и обычном `on_destroy()`. Прикрепление проходит очередью из устойчивых копий ссылок: новые объекты и их дочерние поведения инициализируются до следующего шага физики, без изменения обходящегося списка. Каждый экземпляр получает `on_start` и `on_destroy` не более одного раза. Уничтоженный объект не получает обновления; его поведение удаляется из активного списка перед `on_destroy`. Бесконечная цепочка создания прерывается диагностикой после 8192 объектов за проход прикрепления.

При замене сцены старый `on_destroy` видит собственный World и настройки своей сцены. Созданные там объекты удаляются вместе с прежним миром; изменения паузы, переходов, обработчиков и аудио не переносятся в новую сцену. Захват мыши и screenshot во время teardown игнорируются. Финальный shutdown также выполняет callback по стабильному списку. Состояние Entity.alive остаётся доступно через сохранённые ссылки после удаления объекта.

Для каждого прикрепления файла создаётся отдельный экземпляр Behavior. На один объект можно прикрепить несколько поведений. Все события необязательны. Если класса Behavior нет, события вызываются прямо у Python-модуля; в этом случае сохраните ссылку на объект самостоятельно, например через `forge.find()`.

Порядок: startup on_start → build сцены → on_start сцены → on_start поведений. В кадре: ввод → переход сцены → startup on_update → события on_update сцены/объектов → фиксированная физика и столкновения → удаление/подключение новых поведений → отрисовка. При выходе вызываются on_destroy. Скрипты и Python API работают на главном потоке; не обращайтесь к сцене или графике из фонового потока.

Удаление: `entity.destroy()` немедленно делает alive=false; физическое удаление и on_destroy происходят в конце кадра. Новый объект появляется в мире немедленно, а его поведение подключается в конце кадра. Сохранённая ссылка на удалённый объект остаётся безопасным Python-объектом, но больше не отображается и не выполняет поведение.

## 9. Python API

`import forge` загружает встроенный C++-модуль. Векторы принимаются как tuple/list; возвращаются последовательности. Для изменения компонента прочитайте вектор и присвойте новый целиком.

```python
x, y, z = entity.position
entity.position = (x + 1, y, z)
```

| Функция | Назначение |
| --- | --- |
| spawn(dict) → Entity | Создать объект; prefab доступен |
| find(id) → Entity/None | Найти живой объект |
| entities() → list | Список живых объектов |
| change_scene(path) | Переход в следующем кадре |
| quit() | Завершить цикл |
| dt(), time() | Время кадра и время с начала runtime, секунды |
| is_dev(), is_headless() | Режим запуска |
| key_down(name), key_pressed(name) | Удержание / однократное нажатие |
| mouse_down(button=0) | Кнопка мыши, 0 левая, 1 правая, 2 средняя |
| mouse_scroll() | Колесо: смещение X/Y за кадр |
| mouse_position(), mouse_delta() | Логические пиксели / смещение за кадр |
| capture_mouse(bool) | Захват и скрытие курсора |
| window_size() | Логические размеры окна |
| set_camera(position, target=(0,0,0)) | Камера сцены |
| camera_position() | Положение камеры |
| set_mode('2d'/'3d') | Режим мира; гравитацию настройте отдельно |
| set_gravity(vector) | Ускорение для dynamic-объектов |
| set_background(rgba) | Цвет очистки |
| raycast(origin, direction, distance=1000) | Ближайший AABB-объект или None |
| overlaps(entity_a, entity_b) | Проверить AABB-пересечение |
| play_sound(file, loop=False, volume=1, channel='sfx', fade=0) → id | Аудио из paths.audio, см. 10.4 |
| screenshot(file) | Сохранить следующий отрисованный кадр в PPM (например screenshots/frame.ppm) |
| stop_sounds() | Остановить все звуки |
| log(message, level='INFO') | Одновременно терминал и журнал |
| open_log() | Открыть журнал приложением ОС |
| asset_path(group, file) | Абсолютный путь ресурса |
| project_path(file='.') | Абсолютный путь внутри проекта |
| settings() | Копия конфигурации как dict |
| save(name, value) | JSON-сохранение с атомарной заменой файла |
| load(name, default=None) | Чтение сохранения / значение по умолчанию |

Клавиши: одиночные латинские буквы, цифры, SPACE, ESCAPE, ENTER, TAB, BACKSPACE, LEFT/RIGHT/UP/DOWN, PAGEUP/PAGEDOWN, SHIFT/CTRL/ALT (левые), F1..F25. Неизвестное имя клавиши — исключение. `key_pressed` становится true один кадр. В headless ввод всегда false, позиция мыши (0,0); аудио микшируется без устройства.

Свойства Entity: `id` и `alive` только для чтения; изменяемые `name`, `position`, `rotation`, `scale`, `velocity`, `collider`, `mass`, `color`, `texture`, `model`, `text`, `text_key`, `text_params`, `font_size`, `clip`, `visible`, `dynamic`, `trigger`, `data`. `kind`, scripts и material задаются при создании. Методы: `move(x,y,z=0)`, `impulse(x,y,z=0)` (изменяет скорость на импульс/массу), `destroy()`.

`entity.data` возвращает копию JSON-словаря. Для сохранения изменений присваивайте весь dict обратно. Состояние жизненного цикла хранится в C++ отдельно от data; поля с префиксом `_forge_` остаются зарезервированными для расширений. Хранить Python-объекты или функции в data нельзя: данные должны сериализоваться в JSON.

Примеры:

```python
entity = forge.spawn({'id': 'enemy', 'kind': 'cube', 'position': [0, 1, 0], 'collider': [1, 1, 1]})
forge.log({'stage': 'load', 'progress': 0.75}, 'DEBUG')
forge.save('slot1', {'health': 100, 'scene': 'level.json'})
state = forge.load('slot1', {'health': 100})
path = forge.asset_path('textures', 'portrait.png')
```

## 10. Модули и расширение

`forge.__version__` содержит версию C++-движка из CMake; help и build manifest используют ту же версию. `project.version` в engine.json — отдельная версия вашей игры.

Встроенные низкоуровневые модули — C++-реализации мира, графики, ввода, звука и сохранений, экспортируемые через `forge`. Папка `modules` добавлена в sys.path: общие Python-функции импортируются обычным `import ui`, `import animation`.

Готовые модули: `ui` (Canvas, раскладка и виджеты), `dialogue`, `menus`, `saves`, `settings.AudioSettings`, `audio`; `math3d.add/mul/normalize`; `events.EventBus`; `animation.SpriteAnimation`, `animation.Tween`. Экземпляры Animation/Tween и старый Button(bounds, callback) нужно обновлять из своего on_update. Canvas и новые виджеты работают автоматически. Модули не навязывают жанр, структуру игровых классов или глобальный менеджер.

Например:

```python
from animation import Tween

def on_start():
    global tween
    tween = Tween(forge.find('player'), 'position', (700, 450, 1), 2)

def on_update(dt):
    tween.update(dt)
```

C++-расширение без редактирования ядра:

```cpp
#include <forge/engine.hpp>
FORGE_MODULE(my_math) {
    module.def("lerp", [](float a, float b, float t) {
        return a + (b - a) * t;
    });
}
```

Сохраните файл в своей библиотеке модулей, добавьте относительный путь в `native_modules` и выполните `compile --project ...`. Затем в Python доступно `forge.lerp(...)`. Заголовок содержит типы Config, World, Entity, Runtime; через `forge::active` C++-модуль может получать активный runtime. Проверяйте указатель и соблюдайте главный поток. Регистрация выполняется при старте приложения. Новые имена API не должны конфликтовать с базовыми.

C++-модули компилируются в бинарный файл: это расширение через исходники, а не загрузка произвольных DLL. Это позволяет менять и дополнять низкоуровневую библиотеку без модификации главного скрипта, сохраняя единый способ сборки на двух ОС.

Сторонние Python-пакеты положите внутрь проекта:

```sh
python -m pip install --target python_packages имя_пакета
```

Добавьте `"python_paths": ["python_packages"]`. Пакеты с бинарными расширениями должны соответствовать версии/архитектуре встроенного Python и целевой ОС. Их внешние DLL/dylib и лицензии проверяйте отдельно: автоматическая упаковка произвольных сторонних бинарных зависимостей не гарантируется.

## 10.1. Готовый UI и автоматическая раскладка

Нажмите **3** в стартовой 2D-сцене: откроется `scenes/interface.py`. В примере есть диалог, автоматическое чтение, журнал, меню паузы, настройки громкости, ручные слоты и автосохранение. Escape открывает/закрывает меню. Все эти функции находятся в редактируемых Python-модулях, а не в ядре.

Минимальный интерфейс сцены:

```python
import forge
from ui import Canvas, Column, Row, Label, Button

def on_start():
    global canvas
    root = Column(padding=32, gap=16)
    root.add(Label('Название игры', size=64))
    root.add(Label('Текст автоматически переносится по ширине контейнера.', size=26))
    root.add(Row(
        Button('Начать', lambda: forge.change_scene('game.py')),
        Button('Выход', forge.quit),
    ))
    canvas = Canvas(root, width=1280, height=720)

def on_destroy():
    canvas.close()
```

`Canvas` сам подписывается на кадры. Вызывать его из `on_update` дополнительно не нужно. Для собственного цикла используйте `automatic=False` и вызывайте `canvas.update(dt)`. `close()` отписывает Canvas и уничтожает принадлежащие ему объекты; повторный вызов безопасен. Один виджет принадлежит одному дереву.

| Компонент | Назначение |
| --- | --- |
| `Column(*children, gap=12, ...)` | Вертикальная раскладка |
| `Row(*children, gap=12, ...)` | Горизонтальная раскладка |
| `Label(value, size=24, color=..., wrap_text=True, align='left', ...)` | Текст; выравнивание left/center/right |
| `Button(label, callback, ...)` | Кнопка с наведением, нажатием, disabled и фокусом |
| `Slider(value=1, callback=..., step=.05, ...)` | Значение 0..1; мышь и стрелки |
| `ScrollView(*children, height=..., ...)` | Вертикальная прокрутка и отсечение содержимого |
| `Canvas(root, width=1280, height=720, scale='fit')` | Масштаб, ввод, отрисовка дерева и оверлеев |

Общие параметры: `width`, `height`, `flex`, `padding`, `background`, `visible`, `enabled`. Без размеров используются размер текста или доступная ширина контейнера. `flex=1` отдаёт элементу долю оставшегося места вдоль направления контейнера; несколько flex-элементов делят место пропорционально весу. Фиксированные размеры имеют приоритет для элементов без flex. Обычный `padding` — число, `(horizontal, vertical)` или `(left, top, right, bottom)`. `background` — RGBA; для панелей достаточно `Column(background=..., padding=...)`.

`widget.add(child)` добавляет элемент; `remove(child)` убирает его и уничтожает его графику. Меняйте `label.value`, `button.label`, `widget.visible/enabled`: следующий кадр пересчитает раскладку. Слишком длинные слова разбиваются по символам; `\n` задаёт явный абзац. `ui.measure(value, size)` возвращает `(width, height, line_height)` из метрик того же TrueType-шрифта, который использует рендерер. `ui.wrap(value, width, size)` доступен отдельно от виджетов.

`scale='fit'` сохраняет пропорции проектного Canvas и центрирует его с полями. `stretch` растягивает его по двум осям. `none` использует текущие размеры окна в логических пикселях, без масштабирования. Размер окна и плотность Retina/HiDPI учитываются отдельно. Виджеты и их текст отсекаются по прямоугольникам контейнеров; они не выходят поверх соседних окон. Глифы растрируются под реальный размер текста, масштаба и плотности экрана, а не увеличиваются из 40 px. Высота растра ограничена 1..1024 пикселями; произведение вычисляется в double и ограничивается до преобразования в int. При более крупном тексте используется масштабирование максимального растра. Кеш различает размер и код символа и освобождает глифы при превышении 4096 записей.

Клик новой кнопки срабатывает при отпускании над той же кнопкой; отпускание снаружи отменяет клик. Tab / Shift+Tab переключают фокус, Enter / Space активируют кнопку, Left/Right меняют выбранный Slider. Отключённые элементы пропускаются. Колесо прокручивает ScrollView под указателем; PageUp/PageDown листают его по высоте. `canvas.overlay(widget)` создаёт отдельную центрированную панель, `canvas.modal(widget)` ограничивает ввод этой панелью, `canvas.modal(None)` снимает ограничение. Видимость панели переключается отдельно.

Старые `ui.text`, `ui.panel` и `Button((x,y,width,height), callback).update()` сохранены для совместимости. Старый Button остаётся ручным детектором нажатия; готовая визуальная кнопка создаётся через строковый `label` и дерево Canvas. Низкоуровневый Entity с `kind='text'` по-прежнему использует явные `\n`; автоматический перенос предоставляет Label.

## 10.2. Пауза, диалог, журнал и готовое меню

`forge.set_paused(True)` останавливает startup/scene/Behavior `on_update` и физику. UI, звук, таймер кадра и `forge.on_frame` продолжают работать. `forge.is_paused()` возвращает текущую паузу. Для фоновых UI-сервисов:

```python
listener = forge.on_frame(lambda dt: update_interface(dt))
forge.remove_listener(listener)
```

Обычная подписка относится к сцене и удаляется при её замене. `persistent=True` сохраняет подписку до явной отписки/завершения движка: callback должен сам управлять ссылками на объекты старой сцены. Обработчики вызываются по порядку регистрации до игровых обновлений. Удалённый в этом кадре callback больше не вызывается, добавленный начинает со следующего кадра.

Модуль `dialogue` необязателен:

```python
from dialogue import Dialogue

dialogue = root.add(Dialogue([
    {'speaker': 'Герой', 'text': 'Первая реплика.'},
    {'speaker': 'Друг', 'text': 'Следующая реплика.'},
], characters_per_second=35, auto_delay=1.5, on_done=finish_dialogue, flex=1))
```

Строки без speaker тоже допустимы. `advance()` сначала раскрывает текущую реплику, затем переходит дальше. `toggle_auto()` включает автоматическое чтение: после раскрытия текста ожидание равно `auto_delay + len(text)/80` секунд. Пауза, скрытый виджет и модальная панель приостанавливают чтение. `finished` показывает окончание, `journal.entries` содержит историю, `journal.view(height=...)` создаёт её прокручиваемый вид. `capture()` возвращает JSON-состояние, `restore(state)` проверяет и восстанавливает позицию и журнал. `Dialogue.close()` отключает его таймер; Canvas вызывает это при закрытии дерева.

Готовое меню:

```python
from menus import MenuController
menus = MenuController(canvas, saves=save_manager, capture=capture_game,
                       restore=restore_game, journal=dialogue.journal)
menus.show_pause()  # также вызывается по Escape
```

Сохранения/загрузка/журнал появляются только если переданы соответствующие службы. Меню имеет `show_settings()`, `show_slots(save=False)`, `show_journal()`, `show_about()`, `close_menu()` и `close()`. Слоты 1..5 и auto доступны по умолчанию; число ручных слотов задаёт `slots`. Закрытие меню возвращает предыдущую паузу. Ошибки загрузки показываются внутри меню и логируются как WARN. Перезапись выбранного ручного слота происходит сразу.

`settings.AudioSettings` хранит громкости master/music/sfx/voice/ui в `saves/preferences/audio.json` с проверкой данных и резервной копией. Меню создаёт эту службу само либо принимает `settings=your_audio_settings`. Изменения сохраняются после 0.25 секунды без новых изменений; при `close()` выполняется flush. Повреждённые настройки восстанавливаются из backup или заменяются допустимыми значениями с предупреждением. Дополнительные графические или игровые настройки добавляйте отдельными виджетами и своим SaveManager.

В `on_destroy()` сцены вызывайте `menus.close()`, `save_manager.close()` и `canvas.close()`. Сценарий `scenes/interface.py` показывает полный порядок и связывание модулей. UI и меню можно использовать поверх 2D и 3D; диалог не является обязательной частью движка.

## 10.3. Слоты, версии формата и автосохранение

`forge.save/load` остаются низкоуровневыми. Для игровых слотов используйте независимый модуль `saves`:

```python
from saves import SaveManager, SaveError

saves = SaveManager(
    version=2,
    migrations={1: lambda old: dict(old, coins=0)},
    validate=lambda data: isinstance(data, dict) and 'health' in data,
)
saves.write('1', {'health': 100, 'coins': 8}, title='Глава 2',
            description='Перед входом в город', metadata={'scene': 'city.py'})
try:
    state = saves.read('1')
except SaveError as error:
    forge.log(error, 'WARN')

saves.autosave(capture_game, interval=60, slot='auto')
```

Каталог по умолчанию — `<save_directory>/slots`; свой задаётся `directory`, внутри корня проекта. Идентификатор слота: 1..80 латинских букв, цифр, `_` или `-`. Формат оболочки `forge.slot/1` отделён от версии данных вашей игры. Записываются данные, версия, UTC-время, название, описание, дополнительные metadata и SHA-256 всей оболочки без поля checksum. Размер ограничен 16 MiB, настройка — `max_bytes`. Контрольная сумма обнаруживает повреждение, но не защищает от намеренного изменения сохранения.

Запись выполняется во временный файл с flush/fsync и атомарной заменой. Перед перезаписью предыдущий проверенный слот сохраняется как `.json.bak`; повреждённый основной файл не затирает исправную копию. `read(..., recover=True)` при повреждении/отсутствии основного файла пробует backup и пишет предупреждение. Восстановление возвращает данные backup, основной файл автоматически не переписывает. `recover=False` отключает этот путь. `read('missing', default=...)` возвращает default только при отсутствии основного файла и его резервной копии; повреждение не скрывается значением по умолчанию.

Миграция `migrations[n]` переводит данные n в n+1, пока не достигнута текущая версия. Отсутствующая миграция и более новая версия вызывают `SaveVersion`, повреждение — `SaveCorrupt` или `SaveError`, нарушения схемы — `SaveError`; все наследуются от `SaveError`. Валидатор может вернуть False или выбросить исключение. Миграции не перезаписывают файл автоматически: сохраните проверенный результат сами. Валидатор и restore должны проверять игровые поля до изменения состояния игры.

`saves.info(slot)` возвращает описание и status `empty/ok/recoverable/corrupt`: empty означает отсутствие обоих файлов, ok — исправный основной файл, recoverable — исправный backup при отсутствии или повреждении основного, corrupt — отсутствие исправной копии при наличии повреждённого файла. Для recoverable описание и version берутся из backup, source равен backup, а error описывает проблему основного файла. Готовое меню разрешает загрузку и показывает перевод подсказки восстановления. `info()` и `slots()` не переписывают файлы и не вызывают миграции/игровой валидатор; совместимость версии и игровых данных проверяет `read()`. `saves.slots()` перечисляет объединение основных файлов и backup, без дубликатов; `delete(slot)` удаляет основной файл и его backup. Наличие новой версии видно в `info()['version']`; `read()` проверяет совместимость. Автосохранение регистрирует собственный обработчик кадра. Во время паузы его таймер по умолчанию остановлен (`while_paused=True` меняет это). `close()` отключает автосохранение. Связь данных с объектами сцены задаёт сама игра; сохранение JSON не сериализует автоматически Python-экземпляры или весь World.

## 10.4. Каналы звука, громкость и плавная смена музыки

```python
import audio

audio.master_volume(.8)
audio.music.volume = .5
track = audio.music.crossfade('theme.wav', seconds=1.5)
effect = audio.sfx.play('notify.wav', volume=.3)
effect.volume = .2
effect.fade(0, seconds=.5, stop_after=True)
track.pause()
track.resume()
audio.music.stop(fade=1)
```

Готовы `audio.music`, `sfx`, `voice`, `ui`. Любой именованный канал создаётся через `audio.Channel('ambience')`; `master` зарезервирован для общей громкости. Итоговая громкость — громкость голоса × громкость канала × master. Значения 0..1, длительности затухания конечные и неотрицательные. `Sound.id` — стабильный идентификатор, `playing` — состояние, `volume` — текущая громкость голоса до применения канала/master. `fade` линейно меняет эту громкость, `pause/resume` сохраняют позицию. Fade приостановленного звука тоже приостановлен. Управление игровым состоянием paused само по себе звук не останавливает.

`crossfade` сначала загружает замену, затем затухают предыдущие голоса данного канала и нарастает новый. Ошибка файла замены оставляет предыдущие голоса. Параметры `loop=True`, `volume=1` задают поведение новой музыки. По окончании одноразовые звуки и завершённые stop-fade освобождаются.

Нативный API доступен без Python-обёртки: `play_sound(file, loop=False, volume=1, channel='sfx', fade=0) → id`, `stop_sound(id, fade=0)`, `stop_channel(name, fade=0)`, `channel_sounds(name)`, `set_channel_volume(name, value)`, `channel_volume(name)`, `set_sound_volume(id, value)`, `sound_volume(id)`, `fade_sound(id, volume, seconds, stop_after=False)`, `sound_playing(id)`, `pause_sound(id, paused=True)`, `stop_sounds()`. Несуществующий/завершённый id при командах управления безопасно игнорируется. В headless работает декодирование и микширование без устройства: это позволяет проверять API, но не подтверждает слышимое воспроизведение.

## 10.5. Встроенная локализация

Forge 1.2 предоставляет локализацию непосредственно в C++; Python и готовые UI-модули используют ту же систему. Игра хранит переводы отдельно от сцен, а язык переключается без перезапуска. Русские и английские подписи стандартных меню встроены в бинарный файл и доступны даже без файлов переводов. Проект может переопределить любой ключ и добавить свои языки.

Добавьте необязательную группу `"locales": "locales"` в `paths` и настройте:

```json
"localization": {
  "default_language": "ru",
  "fallback_language": "en",
  "auto_detect": false,
  "save_selection": true,
  "warn_missing": true,
  "languages": {
    "ru": {"name": "Русский", "file": "ru.json"},
    "en": {"name": "English", "file": "en.json"},
    "fr": {"name": "Français", "file": "fr.json"}
  }
}
```

`file` — относительно `paths.locales`; папку и имена файлов можно менять. Настройка языка может быть сокращена до `"fr": "fr.json"`. Объект без `file` регистрирует язык, использующий родительский/резервный словарь. `name` показывается в настройках. Языки `ru` и `en` всегда зарегистрированы; для остальных переведите стандартные ключи `engine.*`, если хотите локализовать меню полностью. Ключи встроенных переводов перечислены в `engine/include/forge/localization_data.hpp`.

Без раздела `localization` старый проект продолжает работать: язык и резервный язык — английский, файлы переводов не требуются. В поставляемом проекте язык по умолчанию русский. `default_language` и `fallback_language` должны быть зарегистрированы.

Пример `locales/ru.json`:

```json
{
  "menu": {"start": "Начать игру"},
  "hello": "Привет, {name}!",
  "inventory": {
    "one": "{count} предмет",
    "few": "{count} предмета",
    "many": "{count} предметов",
    "other": "{count} предмета"
  },
  "literal": "Запись {{name}} содержит фигурные скобки"
}
```

Пример `locales/en.json`:

```json
{
  "menu.start": "Start game",
  "hello": "Hello, {name}!",
  "inventory": {"one": "{count} item", "other": "{count} items"},
  "literal": "The entry {{name}} contains braces"
}
```

Вложенные ключи и записи с точками эквивалентны. Дубли после разворачивания вложенности запрещены. Значение — строка, группа ключей или объект множественных форм `zero/one/two/few/many/other`; форма `other` обязательна. Массивы и числовые значения словаря не принимаются.

```python
import forge, ui

forge.log(forge.tr('hello', name='Аня'))
forge.log(forge.tr('inventory', count=21))  # 21 предмет

# Это ссылка на перевод: Label/Button обновляют подпись и раскладку автоматически.
heading = ui.Label(forge.message('hello', name='Аня'), size=40)
button = ui.Button(forge.message('menu.start'), start_game)
forge.set_language('en')
assert heading.value == 'Hello, Аня!'

# tr() возвращает обычную строку, сохраняющую текст на момент вызова.
fixed = forge.tr('menu.start')
```

Подстановка принимает именованные JSON-параметры `{name}`; имя состоит из ASCII-букв, цифр и `_` и не начинается с цифры. `{{` и `}}` выводят буквальные скобки. Недостающий параметр — исключение, лишние параметры допускаются. Строки вставляются напрямую, остальные JSON-значения — как JSON. Форматирование дат, валют и чисел по региону, ICU MessageFormat, вложенные условия и printf-спецификаторы не реализованы: подготовьте значение параметра в игровом модуле.

Для множественных форм передайте числовой `count`; строки, bool, NaN и infinity не поддерживаются. Движок содержит правила **кардинальных** чисел Unicode CLDR 48 для 224 языковых/региональных записей. Выбор формы использует правило словаря, который предоставил перевод, включая резервный словарь. Целое `1` и число `1.0` могут получать разные формы: JSON сохраняет этот признак, но не произвольное количество завершающих нулей (`1.00`). Отрицательный count классифицируется по модулю, в текст вставляется исходное значение. Компактные записи вроде «1 млн» и порядковые числительные не поддерживаются; CLDR-операнды `c/e` равны нулю. Для собственного языкового кода задайте `"plural_language": "ru"` или `"other"` (единственная форма); неизвестное правило при наличии множественных форм — ошибка проверки проекта. Источник правил: [Unicode CLDR](https://www.unicode.org/cldr/charts/48/supplemental/language_plural_rules.html); данные и лицензия входят в репозиторий и сборку.

| API | Назначение |
| --- | --- |
| `tr(key, **params)` | Получить строку на текущем языке |
| `message(key, **params)` | Создать реактивную ссылку `LocalizedText` |
| `LocalizedText(key, params={})` | То же с явным словарём параметров; `str(value)` переводит в момент вызова |
| `language()` | Текущий нормализованный код |
| `set_language(code, persist=True)` | Переключить язык и связанные Entity; неизвестный язык — исключение без смены состояния |
| `available_languages()` | Список `{'code': ..., 'name': ...}` для селектора |
| `has_translation(key, language='', fallback=True)` | Наличие ключа без предупреждения; пустой language означает текущий |
| `localization_revision()` | Счётчик смен языка/словарей для собственных компонентов |

Коды приводятся к нижнему регистру, `_` заменяется на `-`: `EN_gb` → `en-gb`. При выборе `ru-RU`, если отдельного каталога нет, выбирается зарегистрированный `ru`. Поиск перевода: выбранный код → его родители (`en-gb` → `en`) → резервный код и родители → язык по умолчанию и родители. Без перевода возвращается ключ; при `warn_missing` движок пишет WARN один раз для каждой пары язык/ключ до следующей загрузки словарей. Использование резервного языка тоже диагностируется; переход к родительскому каталогу не является ошибкой.

`auto_detect` использует первый предпочитаемый язык macOS / язык пользователя Windows и выбирает зарегистрированный код либо его родителя. Если совпадения нет, остаётся `default_language`. При `save_selection` сохранённый выбор имеет приоритет над системным и стандартным. Меню `MenuController.show_settings()` автоматически добавляет языковой селектор. Выбор хранится в `<save_directory>/preferences/language.json`; повреждённая или устаревшая настройка игнорируется с WARN. `persist=False` меняет только текущий язык; он не отменяет ранее запрошенный постоянный выбор. `save_selection=False` отключает чтение и запись предпочтения.

Запись предпочтения выполняется через временный файл и атомарную замену после успешной обработки сцены/кадра либо при завершении. Неудачная инициализация сцены возвращает язык и отложенный выбор и не записывает выбор несостоявшейся сцены.

Текст JSON-объектов можно связать напрямую:

```json
{"id": "greeting", "kind": "text", "text_key": "hello", "text_params": {"name": "Аня"}}
```

Python-объекты поддерживают `entity.text = forge.message('hello', name='Аня')` и `entity.set_localized_text('hello', {'name': 'Аня'})`. Свойства `text_key` и `text_params` доступны отдельно; параметры возвращаются копией, изменения нужно присвоить обратно. `text` возвращает актуальный перевод. Присваивание обычной строки в `text` снимает связь с переводом. Для атомарной проверки новой пары ключ/параметры используйте `set_localized_text`; ручное создание некорректной пары вызовет исключение при чтении или обработке кадра. `LocalizedText.params` также возвращает копию.

`Dialogue` принимает `forge.message(...)` в репликах и имени говорящего, сохраняя ключи/параметры в журнале. При смене языка полностью раскрытая реплика остаётся раскрытой; частично раскрытая сохраняет число открытых символов в пределах новой длины. `capture/restore` сохраняет ключи журнала и признак полного раскрытия; обычные строковые реплики продолжают работать. Свободные строки, пользовательские имена и названия старых сохранений сами собой не переводятся. Для собственных сериализуемых данных сохраняйте ключ и JSON-параметры, а не экземпляр `LocalizedText`.

C++-модуль может использовать `forge::active->localization.translate(key, params)`. Самостоятельный `forge::Localization` загружается методом `load(config)` и предоставляет `translate`, `select`, `languages`, `has`, `flush`. При ручном изменении активной C++-локализации обновите объекты через `forge::active->refreshLocalizedEntities()`; Python `set_language` делает это атомарно.

`validate` проверяет словари, формы, скобки, пути и совпадение наборов именованных параметров общих ключей во всех языках. Полнота переводов не обязательна: работает fallback. В режиме `dev` изменение JSON-переводов перезагружает сцену вместе со словарями; при ошибке сохраняются прежний язык, словари, объекты и отложенный выбор. `build` и `init` копируют настроенную папку переводов; игра не загружает CLDR из интернета.

Выбор языка не расширяет возможности шрифтов: замените `renderer.font` на шрифт с нужными символами. Текущий рендерер не выполняет RTL shaping, лигатуры, переключение резервных шрифтов и раскладку сложных письменностей. Словари арабского, иврита и других языков можно хранить и получать через API, но для их корректной отрисовки требуется расширение текстового рендерера. Текстовые переводы не переключают изображения, озвучку и другие ассеты автоматически; это можно сделать игровым модулем по `forge.language()`.

## 11. Физика

`collider` задаёт полные размеры осевого прямоугольника/параллелепипеда с центром в position. В 2D используются X/Y; в 3D требуются положительные X/Y/Z. Коллайдер не наследует scale или rotation. При масштабировании визуального объекта обновите collider самостоятельно.

Dynamic-объекты получают gravity, интегрируются с фиксированным шагом 1/120 секунды и разрешают проникновения по оси минимального пересечения. Масса используется для распределения коррекции и импульса. Static-объекты не двигаются физикой. Trigger генерирует начало/конец контакта без коррекции. Неположительная ширина или высота отключает коллайдер; в 3D также требуется положительная глубина. Это правило одинаково для контактов, overlaps и raycast; уничтоженные объекты исключаются. Проверка пар выполняется только для активных коллайдеров, поэтому UI без collider не участвует в переборе пар. Промежуточные вычисления физики выполняются в double. Перед записью координат/скорости проверяется диапазон float; при переполнении движок выводит ошибку с id объекта и сохраняет прежние значения этой операции, вместо записи NaN/Infinity. В dev действует стандартная пауза при ошибке.

Это простая AABB-физика: без вращательных тел, трения, упругости, суставов, сложных mesh-коллайдеров и непрерывного collision detection. Быстрый маленький объект может пройти сквозь препятствие. Для сложного шутера/хоррора добавьте специализированный физический модуль через C++ API либо реализуйте нужную модель поведения в Python. Свободная камера стартовой 3D-сцены специально не является физическим контроллером персонажа.

## 12. Логи и диагностика

Каждый запуск дописывает журнал `forge.log` в корень проекта; в собранной игре — рядом с `game.json` и Game. Сообщения имеют время и уровень INFO/WARN/ERROR/DEBUG. `forge.log()` и обычный `print()` попадают и в терминал, и в файл. `sys.stderr` также перехватывается. Частичная строка print без перевода строки выводится при flush или завершении.

```python
import forge
forge.log('Начинаем загрузку')
forge.log('Необязательный ресурс отсутствует', 'WARN')
print('Прогресс:', 50, '%')
```

Уровень ERROR у пользовательского `forge.log()` сохраняет сообщение, но сам по себе не завершает игру и не открывает журнал. Необработанное исключение выполняющегося скрипта/ядра сохраняет диагностическое сообщение, открывает журнал через системное приложение и завершает run с кодом 1. В dev исключение on_update приостанавливает выполнение и ждёт исправления файла. Файл открывается один раз за сессию. При неуспешном открытии путь и предупреждение остаются в терминале. Ручное открытие: `forge.open_log()`.

При сборке/validate ошибки JSON, отсутствующие файлы и SyntaxError идут в терминал и журнал с кодом 1; автоматического открытия журнала для этих команд нет. Launcher сохраняет полный вывод компилятора CMake/MSVC/Clang, включая номера файлов и строк.

Для управляемого выхода используйте `forge.quit()`. Не вызывайте `sys.exit()` из игрового скрипта: SystemExit будет обработан как ошибка скрипта.

Журнал требует прав записи в корень игры. Необработанные нативные аварии вроде SIGSEGV, принудительное убийство процесса или отказ ОС не гарантируют открытие файла: обычная обработка исключений не заменяет crash reporter. Для готового продукта добавьте платформенный crash reporting отдельным модулем.

## 13. Разработка без build и reload

`dev` проверяет изменения примерно каждые 0.3 секунды игрового времени. Наблюдаются settings-файл и файлы групп paths, кроме Python bytecode. Изменение сцен, Python-поведений, импортируемых модулей, объектов, материалов, моделей, текстур, шейдеров, шрифта или словарей локализации перезагружает текущую сцену. Если изменён entry_scene, загружается новая первая сцена.

Reload пересоздаёт объекты и экземпляры Behavior: локальное состояние сцены сбрасывается. Для сохранения прогресса используйте save/load. Startup-скрипты живут всю сессию: чтобы поменять их код, перезапустите dev. Размер/заголовок/полноэкранность окна также применяются при следующем запуске. Изменение C++ требует compile и перезапуска.

Неверный Python-код, JSON или шейдер при reload сохраняет ошибку и приостанавливает игровую логику. Исправьте файл: следующая проверка повторит reload. Если ошибка произошла уже в on_update, используется тот же механизм восстановления. Ошибка самой первой загрузки завершает процесс: исправьте и запустите снова. При успешной загрузке новой сцены вызывается on_destroy старой.

Reload сначала подготавливает графику, создаёт новую сцену и инициализирует её поведения и проверяет используемые модель/текстуры до переключения мира. При неудаче восстанавливаются прежний World, скрипты, настройки, sys.path/sys.modules, обработчики кадра, пауза/запрос перехода, состояние захвата мыши/запрос screenshot, голоса и громкости, язык, словари локализации и отложенный выбор языка. Подготовленные шейдеры, текстуры и шрифт заменяют прежние только после успеха. Аудио-команды из инициализации применяются после успеха. При неудаче можно реализовать `on_reload_failed(message)` у старой сцены/Behavior/startup для диагностики восстановленного состояния. Игровые обновления остаются приостановлены до исправления.

Граница транзакции — управляемое состояние движка. В Forge 2.0 `forge.save` и `SaveManager.write` во время hot reload откладывают запись до успешного переключения сцены; при отказе записи отменяются. Для своего persistence используйте `forge.defer_persistence(callable)`. Произвольные open()/Path.write_text(), сетевые запросы, изменения внешних объектов startup и прошедшее время воспроизведения существующего звука автоматически не откатываются. Не размещайте такие необратимые операции в build()/on_start кандидата без явного defer. Изменённые на диске исходники/assets тоже не восстанавливаются из памяти. Для прекращённого из-за ошибки reload графика прежней сцены остаётся отрисовываемой.


При reload движок заменяет свои записи в sys.path без накопления дублей, удаляет прежние пути после изменения каталогов и сохраняет остальные пути, добавленные игровым кодом. При неудаче возвращаются прежние sys.path и список путей, которыми управляет движок.

Импорты из modules/scripts/scenes очищаются при reload. При удалении/замене python_paths очищаются также кешированные модули и namespace-пакеты из отключённых каталогов; пакеты из оставшихся дополнительных путей сохраняются в кеше, включая нативные расширения. startup-модули могут держать старые импортированные ссылки: перезапускайте процесс для их обновления. Файлы из дополнительных python_paths автоматически не наблюдаются.

## 14. Build и распространение

```sh
python tools/forge.py build --output dist/MyGame
```

Перед упаковкой проверяются все копируемые папки из paths и python_paths. Выходная папка не может находиться внутри любой из них или заменять исходный проект/его родителя. Пути нормализуются относительно корня проекта: допустимый алиас вида ../Project/modules становится modules и в плане копирования, и в game.json. Назначение каждого копирования ресурсов и иконки отдельно проверяется на принадлежность временной сборке. Пути paths/python_paths, project.icon и save_directory в упакованной конфигурации используют нормализованные имена.

Готовый каталог содержит `Game` / `Game.exe`, `game.json`, все настроенные папки ресурсов, дополнительные python_paths, приватный `runtime`, лицензии, manifest.json с SHA-256 файлов и START.txt. Исходники ядра и CMake не нужны игроку. Python исходники игрового контента входят в сборку: упаковка не является защитой интеллектуальной собственности.

На macOS:

```sh
cd dist/MyGame
./Game
```

На Windows запустите Game.exe. По умолчанию он откроет окно игры; отдельная команда run не нужна. Исполняемый файл определяет проект по game.json рядом с собой независимо от текущей рабочей папки. Все файлы сборки переносите вместе. Python на машине игрока не требуется; переменные PYTHONHOME/PYTHONPATH игнорируются приватным интерпретатором.

Сборка выполняется сначала во временной соседней папке и переносится в конечное место только после успеха. Существующая output-папка не перезаписывается. Для новой версии выберите новое имя или явно удалите старую сборку. Output не может быть корнем исходного проекта, его родителем или папкой внутри ассетов.

macOS: библиотека Python и её нативные расширения копируются, зависимости Mach-O переписываются на относительные пути, изменённые бинарные файлы подписываются ad-hoc. Это обеспечивает локальный запуск; для публичного распространения нужны ваша Developer ID подпись, notarization и, если требуется, оформление `.app`/`.dmg`. В текущей версии каталог запускается бинарным файлом из терминала.

Windows: копируется Python DLL, стандартная библиотека, DLLs и присутствующие рядом runtime DLL. Для MSVC runtime, отсутствующего в поставке выбранного Python, установите Microsoft Visual C++ Redistributable на машине игрока или обеспечьте разрешённую app-local поставку.

Нельзя собрать Windows .exe обычным build на macOS или наоборот. Скомпилируйте движок и соберите игру отдельно на каждой целевой ОС/архитектуре. Для этого добавлен `.github/workflows/build.yml` с macOS и Windows, интеграционными тестами и артефактами. Сам факт наличия workflow не означает, что Windows проверена на этом компьютере.

Сборка содержит выбранную установленную стандартную библиотеку CPython; её размер может составлять десятки мегабайт. Папка игры должна быть доступна для записи лога и сохранений. Размещение под защищённым Program Files без переноса пользовательских данных не поддерживается базовой схемой.

## 15. Шейдеры

По умолчанию используются graphics/default.vert и default.frag. Если поля vertex_shader/fragment_shader удалены, используются встроенные эквиваленты. Пользовательские шейдеры должны использовать GLSL 330 Core и интерфейс:

- атрибуты: location 0 — vec3 position, 1 — vec2 UV, 2 — vec3 normal;
- uniform mat4 u_mvp, u_model;
- uniform vec4 u_color;
- uniform sampler2D u_texture, int u_textured;
- uniform float u_lit (0 для 2D/UI, 1 для 3D).

Убираемые компилятором unused uniforms допустимы. Один shader program используется для всех типов объектов, включая текст. Ошибки GLSL выводятся с именем файла и текстом OpenGL-компилятора. Не задавайте нулевой scale для рисуемого объекта: стандартный шейдер использует inverse(u_model).

Текст декодируется из UTF-8; глифы создаются на запрос через stb_truetype и кешируются. Noto Sans поддерживает латиницу и кириллицу. Наличие иных символов зависит от шрифта. Лигатуры, RTL shaping и цветные emoji не реализованы. Для текста position — левый верхний угол, перенос строки поддерживается через `\n`. Автоматический перенос и выравнивание предоставляет ui.Label. Растеризация учитывает размер текста, scale и HiDPI. `entity.clip = (left, top, width, height)` ограничивает экранный объект логическим прямоугольником; `None` убирает ограничение.

### 18.1. Камеры, UV, постобработка и uniforms

```python
monitor = forge.set_render_target('door', {
    'width': 640, 'height': 360, 'mode': '3d',
    'position': [5, 3, 5], 'target': [0, 1, 0], 'fov': 60,
    'include_ui': False, 'layers': 1,
})
forge.spawn({'texture': monitor, 'screen': True,
             'position': [900, 180, 0], 'scale': [480, 270, 1]})
forge.remove_render_target('door')  # сначала удалите или смените использующие его текстуры
```

Камера имеет собственный color/depth framebuffer и каждый кадр рисует мир. Размеры — целые 1..4096, fov — 1..178 градусов, mode — 2d или 3d. 2D использует координаты своей текстуры и position как смещение. `Entity.layer` — 32-битная битовая маска: объект виден при пересечении с маской камеры. Камеры рендерятся в порядке имён; собственная текстура камеры исключается из её прохода, другие камеры могут показывать предыдущий кадр. Циклический граф камер не вычисляется рекурсивно. Имена `@target:name` используются только как texture, файлы по ним не открываются.

`entity.uv = (u, v, width, height)` задаёт область текстуры в нормализованных координатах 0..1 с началом сверху слева. Регион не может выходить за границу. Это работает для спрайтов, mesh и screen-объектов. Пакетирование объединяет соседние совместимые спрайты/глифы без изменения порядка отрисовки; texture, color, clipping, depth, камера и uniforms определяют границы батча. Глифы хранятся в GPU-атласах; увеличенный текст растеризуется под свой размер и HiDPI до 1024 px.

```python
from animation import SpriteSheet
sheet = SpriteSheet('actor.png', columns=8, rows=4, frames=range(8))
animation = sheet.animate(actor, fps=12, loop=True)
def on_update(dt): animation.update(dt)

forge.set_postprocess({'grain': .12, 'bloom': .2, 'aberration': 2,
                      'scanlines': .3, 'vignette': .25, 'fade': 0, 'gamma': 1})
forge.set_shader_uniform('custom_tint', [.2, .8, .5, 1.])
actor.uniforms = {'custom_amount': .4}
```

Postprocess — отдельный полноэкранный проход с UV/`u_texture`, `u_time`, `u_resolution`; шейдер можно заменить через `renderer.post_shader`. Grain, scanlines, vignette, fade: 0..1; bloom: 0..4; aberration: 0..32 pixels; gamma: .1..8. `enabled=False` выключает проход. Bloom — пороговый фильтр ярких соседних пикселей, не HDR pyramid. Для shader uniforms поддерживаются bool, signed int32, float и векторы 1..4 float; тип должен совпадать с GLSL (`1.0` для float, `1` для int). Глобальные uniforms лежат в rendering.uniforms, объектные — в Entity.uniforms, постобработки — postprocess.uniforms. Зарезервированные `u_*` управляются движком; для своих параметров выбирайте другие имена.

В engine.json `renderer.fallback_fonts` содержит список дополнительных TTF из graphics. Поиск глифа идёт от основного font к резервным; если символа нет нигде, в терминал и лог однократно выводится `Missing glyph U+...`. Перенос/измерение используют тот же выбор шрифта. Сложный shaping, bidi/RTL и цветные emoji пока требуют другого text backend. Лицензию каждого добавленного шрифта включайте в поставку.

### 18.2. Ресурсы и бюджеты

```python
from assets import AssetHandle, ScenePreloader
loader = ScenePreloader.scene('level.json')  # ресурсы JSON-сцены, prefab, материалы, текстуры модели
# Не блокируйте экран загрузки: опрашивайте loader.progress/ready из on_frame.
if loader.ready: forge.change_scene('level.json')
# loader.close() освобождает pin; кеш может использовать ресурс дальше.

with AssetHandle('audio', 'intro.srt') as handle:
    data = handle.wait(timeout=10).bytes()
```

ScenePreloader принимает также список `(group, file)`; Python-сценам задайте его явно. JSON поддерживает `preload: [{"group":"audio","file":"intro.wav"}]`. `AssetHandle.info` содержит queued/loading/ready/failed, bytes, error, path, group; у изображения width/height, у модели структуру model_info. `wait()` предназначен для подготовки/тестов, не для каждого игрового кадра. Четыре worker thread читают/декодируют ресурсы без OpenGL; GPU upload всегда выполняет renderer на главном потоке. Дополнительные Python-пакеты не нужны.

`asset_budget_bytes` (по умолчанию 256 MiB) ограничивает резидентный CPU-кеш, `renderer.gpu_budget_bytes` (128 MiB) — учтённые GPU-ресурсы. `forge.set_asset_budget(bytes)` меняет CPU-бюджет; `forge.asset_stats()` показывает handles, entries, workers, loading и resident_bytes. Pin через живой handle защищает ресурс от LRU-вытеснения; вызовите close/context manager для предсказуемого освобождения. Недостаток бюджета возвращает явную ошибку. Бюджеты не включают все аллокации CPython/Assimp/драйвера и временный пик декодирования четырьмя worker. `validate/build` полностью декодируют и проверяют контент перед поставкой. run/dev/edit проверяют структуру и ссылки, затем готовят только ресурсы текущей сцены; будущие сцены могут загружаться через ScenePreloader в фоне. Перед commit reload подготавливаются модели, их текстуры, используемые глифы и framebuffer, поэтому ошибка ресурса сохраняет прежнюю сцену. Preload не заменяет валидацию файла.

### 18.3. Свет, модели и skeletal animation

```python
forge.set_lights([
    {'type':'directional', 'direction':[-.5,-1,-.3], 'color':[1,.9,.8],
     'intensity':1, 'shadows':True, 'shadow_extent':20},
    {'type':'point', 'position':[3,2,0], 'color':[1,.2,.1], 'range':10, 'intensity':2},
    {'type':'spot', 'position':[0,4,0], 'direction':[0,-1,0], 'range':20, 'cone':30}
])
info = forge.model_info('actor.glb')
actor = forge.spawn({'kind':'mesh', 'model':'actor.glb'})
forge.play_animation(actor, info['animations'][0]['name'], speed=1, loop=True)
forge.pause_animation(actor)
actor.animation_time = .5
```

Поддерживаются OBJ, glTF 2/GLB, FBX и COLLADA/DAE через Assimp: иерархия узлов, базовый цвет, diffuse/base-color текстура, embedded textures, skin weights и TRS animation clips. Неизвестный clip вызывает ошибку. `model_info` возвращает части, число вершин/костей, клипы с длительностями, внешние текстуры и размер. `animation_pose(file, clip, seconds, loop)` возвращает глобальные матрицы узлов для инструментов; `Entity.animation`/`animation_playing` доступны для чтения. В каждом mesh до 128 костей и 4 весов на вершину; поддержан предел 2M исходных вершин. Скиннинг выполняется vertex shader на GPU. Движок интерполирует переведённые Assimp ключи TRS, без blend trees, morph targets и полного воспроизведения glTF cubic-spline tangents.

Все внешние зависимости модели должны находиться внутри проекта. Поддержка конкретных материалов и версий FBX зависит от импортера; ошибки содержат путь и сообщение Assimp. PBR/normal maps/metallic-roughness, retargeting и смешивание анимаций не реализованы: замените shaders/model module под требования игры.

До 16 point/directional/spot lights, rendering.ambient задаёт окружающий RGB. Одна PCF shadow map доступна для первого directional light с shadows=True. rendering.shadow_size — 64..4096, shadow_extent определяет ортографический охват вокруг camera target. `Entity.casts_shadow=False` исключает объект из depth pass. Тени непрозрачные: текст и screen UI исключены, alpha-cutout/multiple shadow maps/cascades пока отсутствуют. При пустом lights сохраняется прежнее базовое освещение.

### 18.4. Контроллер персонажа и AI

```python
from character import CharacterController
from ai import Scheduler, StateMachine, Timeline, Sequence
controller = CharacterController(player, speed=5, jump_speed=6, automatic=False)
controller.walk(horizontal, forward)  # нормализация диагонального движения
controller.jump()                    # только при grounded
controller.update(dt)

scheduler = Scheduler(budget=64)      # по умолчанию автоматический on_frame
scheduler.every(.2, update_enemy)
scheduler.call_later(2, open_door)
state = StateMachine({'idle':{'update':idle_update}, 'chase':{'update':chase_update}}, 'idle')
state.change('chase'); state.update(dt)
sequence = Sequence([(1, show_title), (2, hide_title)])
sequence.update(dt)
```

`forge.move_character(entity, delta, skin=.001)` выполняет swept AABB по X/Z/Y, ограничивает движение стенами, скользит по свободным осям и возвращает position/grounded/hits с id и normal. `CharacterController` делает тело кинематическим, добавляет gravity/скорость/прыжок. Для 2D дайте коллайдеру положительный Z, движок игнорирует эту ось столкновений. Это AABB controller: нет capsule, slope/step climbing, вращающихся тел и автоматического устранения начального глубокого проникновения. Создавайте персонажа вне препятствий. `forge.set_physics_enabled(False)` выключает физику отдельно от UI/скриптов; `forge.physics_enabled()`/gravity() доступны для чтения.

Scheduler использует детерминированный порядок таймеров и лимит callback за кадр. Пропущенные периоды repeating-задач не создают неограниченную очередь догоняющих вызовов. Пауза останавливает scheduler, кроме `run_paused=True`; automatic=False позволяет управлять clock самостоятельно. StateMachine вызывает enter(previous), exit(next), update(dt), event(name,...); рекурсивные переходы запрещены. Timeline принимает `(time, callback)`, duration/loop, seek(seconds); Sequence принимает последовательные `(delay, callback)`. Для циклического fast-forward действует предел 1024 циклов за update. Эти модули не задают жанр или алгоритм поиска пути. При удалении сцены вызывайте close у долгоживущих компонентов.

### 18.5. Ввод, переназначение и replay

```python
from input_actions import ActionMap, InputRecorder, InputReplay
replay = InputReplay('replay/test.json')  # если нужен replay, создайте до подписчиков-потребителей
actions = ActionMap({'jump':['key:SPACE','pad:0:a'],
    'move':[{'input':'key:A','scale':-1}, 'key:D', 'axis:0:left_x']})
if actions.pressed('jump'): controller.jump()
actions.bind('jump','key:J'); actions.save(); actions.load()
```

Поддержаны key:NAME, mouse:0..7, pad:0..15:a/b/x/y/... и axis:0..15:left_x/left_y/right_x/right_y/left_trigger/right_trigger. Стандартные gamepad mappings предоставляет GLFW; специального драйвера движок не требует. ActionMap.value даёт -1..1; trigger axes нормализуются из GLFW -1..1 в 0..1, чтобы отпущенный trigger не активировал action. down/pressed/released учитывают переходы; deadzone по умолчанию .15. Контексты задаются bind(..., context='menu'), push_context/pop_context; активен верхний контекст. Сохранение bindings использует SaveManager.

`forge.input_snapshot()` — копия реального кадра с keys/pressed/released, мышью (buttons/position/delta/scroll), gamepads и events (key/mouse_button/text/scroll). `forge.input_events()`/gamepads() дают соответствующие массивы. Recorder подписывается на on_frame и сохраняет все данные; `record.save('replay/session.json')` пишет versioned JSON, max_frames по умолчанию 360000. Replay подставляет записанный кадр через forge.inject_input, включая dt; автоматические потребители, созданные позже, видят replay. automatic=False даёт явный порядок update: replay → actions → игровая логика → recorder. После окончания finished=True; close снимает подписку. Воспроизводится ввод и dt, не весь мир: фиксируйте seed случайности, начальное состояние, порядок callbacks и асинхронные результаты для воспроизводимых регрессий.

from ui import Canvas, Theme, Column, Button, Label, ScreenStack
canvas = Canvas(Column(), theme=Theme({'Button':{
    'background':(.1,.15,.2,1), 'hover':(.2,.4,.3,1), 'transition':.15}}))

Theme задаёт цвета класса; Widget.style переопределяет свойства конкретного элемента. Button использует background/hover/pressed/disabled, color/disabled_color и время transition. Общая opacity Widget умножается на opacity родителей. ### 18.7. Пространственный звук, DSP и субтитры

```python
from audio import voice, music
from subtitles import Subtitles
sound = voice.play('intro.wav', pan=-.5, position=(-2,1,0),
                   lowpass=2000, highpass=100, echo_seconds=.12,
                   echo_decay=.3, echo_wet=.25, stream=True)
sound.pan=.5; sound.position=(2,1,0); sound.configure(pitch=1.1)
caption = Subtitles(sound, 'intro.srt', label)
forge.set_audio_listener((0,1,0),(0,0,-1))
```

Звук поддерживает pan -1..1, pitch .01..8, spatial/position, min_distance/max_distance, lowpass/highpass (0 выключает, 20..23999 Hz), echo_seconds 0..5, echo_decay 0...95, echo_wet 0..1. DSP — реальные miniaudio nodes: фильтры второго порядка и delay. Источник без spatial сохраняет обычное стерео. `sound.info`/forge.sound_info дают options, cursor/duration, volume, paused/playing, channel и streaming. Автоматическое следование listener за камерой включается audio_settings.follow_camera.

В engine.json audio_settings задаёт max_voices (1..1024), channel_limits, overflow (`steal_oldest`/`reject`), streaming (`auto`/`stream`/`decode`), stream_threshold_bytes. Индивидуальный stream переопределяет политику. При переполнении выбирается старейший голос с минимальным priority, при равном priority; более приоритетный голос не вытесняется низкоприоритетным. Отказ возвращает sound id 0. Сначала остановите/освободите ненужные loop sounds. `configure_audio({...})` меняет политику; `audio_stats()` показывает voices/streams/DSP/stolen/dropped/duck_gains.

Ducking: `{'source':'voice','target':'music','gain':.3,'attack':.05,'release':.5}` в audio_settings.ducking уменьшает громкость музыки при активной речи и плавно возвращает её. Субтитры принимают SRT либо JSON `[{'start':0,'end':2,'text':'...'}]`; JSON допускает key/params для локализации. Они сверяются с реальным playback cursor, сохраняются при pause и очищаются после stop/end. Если для streaming-декодера ещё нет данных, курсор не продвигается и подпись также ждёт; записанный InputReplay не воспроизводит звуковое устройство побайтно.

### 18.8. Persistence, каталоги и ошибки

`storage: {"mode":"user","application_id":"com.example.game"}` направляет forge.save/SaveManager/настройки/локализацию в пользовательский каталог. Для совместимости mode по умолчанию project. На macOS data/config/saves используют `~/Library/Application Support/<id>`, cache — Library/Caches, logs — Library/Logs; Windows использует LOCALAPPDATA, при его отсутствии APPDATA. `user_path(kind, relative='')` всегда возвращает пользовательский путь независимо от mode; kind=data/saves/config/cache/logs, `storage_path(relative)` учитывает mode. Подкаталоги из relative остаются внутри выбранного корня, выход через ../ и symlink запрещён. API возвращает путь, при собственной записи создайте parent. `FORGE_USER_ROOT` переопределяет базу для тестов. У приложения должен быть стабильный уникальный application_id.

Во время hot reload `forge.save` и SaveManager.write замораживают данные и записывают после commit; отказ кандидата удаляет его очередь. Читать новое сохранение с диска до commit нельзя. `forge.defer_persistence(lambda:...)` поддерживает собственную атомарную запись; callable вызывается после успешной загрузки, а вне загрузки — сразу. Не захватывайте изменяемые данные без копии. Очередь успешного commit выполняется последовательно: ошибка одной записи логируется, но уже выполненные записи не откатываются и остальные продолжаются. Произвольные filesystem/network операции Python вне этого API остаются ответственностью игры.

`WindowSettings` из settings сохраняет разрешение, fullscreen и vsync; MenuController включает эти настройки. `forge.set_window({...})` применяет их к окну, window_settings() показывает текущее состояние. Fullscreen использует видеорежим основного монитора. Успешные пользовательские настройки не меняют engine.json. На headless изменение физического окна пропускается.

`forge.profile()` возвращает время callbacks/audio/scripts/physics/frame и статистику assets/renderer. `renderer_stats()` показывает draw_calls, batches, triangles, gpu_bytes/budget, glyphs/pages, render_targets и render_ms. Это CPU wall time, а не GPU timestamp; frame_ms не содержит ожидание следующего кадра.

Необработанные runtime-ошибки создают JSON в crash-reports возле текущего лога с версией, сценой, временем, профайлером и сообщением (для Python — traceback); обычное поведение открытия журнала сохраняется. `forge.crash_report(message)` создаёт отчёт вручную. Fatal native signal/exception сохраняет native-last.txt; стек системного падения следует искать в OS crash report/Windows Error Reporting. C++ signal handler использует отдельный стек и безопасную запись, без Python/GL во время падения. Отчёты могут содержать игровые пути и сообщение: отправка куда-либо всегда выполняется отдельно разработчиком/пользователем.

### 18.9. Редактор сцен

`edit --scene editor-empty.json` открывает оконный редактор, при старте симуляция остановлена. Hierarchy выбирает объекты; Inspector редактирует transform, collider, цвет, видимость, screen/dynamic/trigger/casts_shadow и текст. Add/Duplicate/Delete, браузер textures/models/scenes, свет, camera, gravity, Undo/Redo (до 100 снимков), Play preview и Save JSON доступны в окне. Средняя кнопка мыши перемещает камеру, WASD — движение, Ctrl+S/Cmd+S сохраняет выбранное JSON-имя внутри scenes. Изменения файлов в dev/edit проходят обычный hot reload.

Редактор сохраняет декларативный снимок мира через `scene_data()/save_scene(file)`, включая scripts/data сущностей и существующий JSON scene.script. Исходный Python-код и closure/state не сериализуются. Объекты, созданные скриптом во время выполнения (включая UI), попадают в снимок: для авторской сцены начните с editor-empty.json и подключайте Behavior через scripts/data JSON или код. При preview скрипты могут менять мир; undo применяется при остановленной симуляции к данным сцены, без восстановления произвольного состояния Python. Отключение preview останавливает симуляцию, не возвращает её автоматически к начальному состоянию; Reload загружает исходный файл. Это редактор объектов и сцены, без visual scripting, shader graph, animation graph и gizmo-манипуляторов.

### 18.10. Приложение macOS и подпись

```sh
python tools/forge.py build --output dist/MyGame.app
open dist/MyGame.app
python tools/forge.py sign --output dist/MyGame.app --identity 'Developer ID Application: Your Name (TEAMID)'
python tools/forge.py notarize --output dist/MyGame.app --keychain-profile your-stored-profile
```

`.app` включает Contents/MacOS/Game, Info.plist/PkgInfo, Resources/game.json, runtime, контент и ICNS из project.icon. Конвертация иконки использует sips/iconutil и требует доступных системных сервисов macOS. Wrapper не зависит от shell или текущей рабочей папки. App автоматически включает storage.mode=user. Папка остаётся поддерживаемым форматом build на macOS/Windows; на Windows запуск Game.exe использует app-local CPython DLL.

Локальная упаковка ставит ad-hoc signature, которая подтверждает целостность, но не заменяет Developer ID/Gatekeeper notarization для публикации. `sign` подписывает вложенный Mach-O внутри-out, включает hardened runtime и entitlements для динамических библиотек Python, обновляет manifest и запечатывает bundle. `notarize` создаёт ZIP через ditto, вызывает notarytool --wait и stapler; credentials заранее храните в Keychain средствами Apple, не в engine.json. Нужны реальный сертификат и аккаунт Apple Developer. Команды их не создают. На этом выпуске подтверждены только локальная ad-hoc подпись и автономный запуск.

Для каталогов manifest.json хранит SHA-256 файлов; у `.app` manifest размещён в Resources, пути считаются от корня bundle. Исполняемый Game и CodeResources перечислены в signature_managed_files: внешняя подпись изменяет их и проверяет их целостность. Для приложения используйте также `codesign --verify --deep --strict MyGame.app`. Удалять файлы CPython или лицензии из bundle нельзя.
